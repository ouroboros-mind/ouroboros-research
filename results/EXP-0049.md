## Question

On the new model, which parts of the mind's working frame help or hurt, and can a validated, model-specific frame stay close to the raw model while the regrown skill adds on top?

The frame had five parts: a goal line, procedure, self line, three retrieved memories, and a combined thinking-note-plus-resources line. This test follows EXP-0048's partial result and separates the frame from the cache that grew inside it.

## Protocol (conceptual)

1. Test balanced combinations of the five frame parts on fresh development tasks.
2. Apply a frozen selection rule: keep a part by default, and switch it off only for a pre-registered harmful effect after correction for multiple comparisons.
3. Publish the chosen profile's hash before the final test.
4. Compare the raw model, old full frame, validated frame, and both frame-plus-cache combinations on fresh final tasks.
5. Check the selected frame on unseen task families, then check general capability, identity, selection-rule compliance and the stored mind.

Task construction, cache details, runtime settings, gate thresholds and kernel internals are withheld.

## Results

Classified NOT SUPPORTED. The pre-registered decision was "the frame still costs the new model". The validated frame failed both its comparison with raw and its comparison with the old frame. Its cache passed inside the validated frame, but did not show transfer on the secret rotating test. The candidate profile was not activated.

## Deviations from the pre-registration

Five amendments were published as hash commitments before the code each fixed ran: a token counter the model's chat template refused; a post-run audit crash recovered by replaying recorded replies, with 0 verdict differences; a replay loader fix; a type error in the final integrity stage; and a check that had compared against the latest amendment rather than the original entry.

## What this does not show

- **A working frame without cost on this model.** The selected frame still scored below the raw model.
- **That frame parts add independently.** Their interactions were about as strong as their individual effects. The additive prediction of +6.6 points failed, and the selected configuration's development result already showed no gain.
- **Transfer of the cache.** Its small apparent gain on unseen families was not significant.
- **A general migration result.** This is one model family and one model-specific frame.

## Reading

The frame's cost is real on a common request path. This closes the harness difference left open by EXP-0048: the old raw path was 3 points worse than the common one, not better. Switching parts off one at a time did not remove the cost. The cache is entangled with the frame it grew in, adding more inside its old full frame than inside the validated one.

A neutral text control of the frame's length cost about half as much as the frame on development tasks. It is a reported control, not a gate. Its text was rebuilt offline and was not re-checked against the live server.

After migration, the same persistent mind accumulated verified experience on the new cortex and regrew a cortex-native neural skill that improved performance beyond the raw cortex, while the persistent working frame still imposed a measurable cost.

The proposed next question, pending owner decision, is whether a different frame presentation, including placement, compression and memory policy, can work when the skill is regrown inside each candidate frame. Cross-family skill regrowth waits for that.
